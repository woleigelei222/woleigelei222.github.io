# ThinKV 精读（一）：从思考类型识别到自适应 KV 量化

> **学习日期：** 2026 年 10 月 21 日  
> **论文：** *ThinKV: Thought-Adaptive KV Cache Compression for Efficient Reasoning Models*  
> **发表：** ICLR 2026  
> **今天实际学习的重点：** 研究动机、Thought Decomposition、Attention 稀疏度、离线 KDE 与在线分类、TBQ（Think Before You Quantize），以及量化与生成长度的关系。  
> **进度说明：** 今天的记录只引出了 TBE（Think Before You Evict），尚未把它的完整淘汰规则作为已学内容。

## 一、今天为什么开始读 ThinKV？

前一阶段学习 KV Cache 优化时，我更多关注的是：**哪些 Head 对历史信息更敏感，以及怎样为不同 Head 分配缓存预算。** 这次读到的 ThinKV 换了一个观察维度：**同一个推理过程中的不同思考片段，是否应该采用相同的压缩策略？**

这个问题出现在长输出的推理模型中尤为明显。模型不仅需要处理输入 Prompt，还可能在 Decode 阶段生成数千乃至数万枚用于分析、计算、纠错的 token。每生成一个新 token，各层还需要产生并维护新的 Key/Value（KV）表示。随着输出变长，缓存占用和内存访问压力都会增加。

ThinKV 的出发点不是简单地“把所有 KV 都变小”，而是考虑 **Reasoning（推理）、Execution（执行）和 Transition（转折）** 对后续推理可能承担不同作用，因此应当采用差异化的保存方式。

今天我想弄清两个关键问题：

1. 模型如何在不依赖固定关键词的情况下，判断当前属于哪一种思考类型？
2. 识别思考类型后，怎样在节省 KV 空间的同时，避免低精度影响后续推理？

## 二、从 Attention 稀疏度观察三种 Thought

### 2.1 三种思考类型

论文把长链式推理中的思考模式归纳为三类：

| 类型 | 英文 | 便于理解的含义 | 论文观察到的 Attention 稀疏度 |
| --- | --- | --- | --- |
| R | Reasoning | 分析条件、构建推理路径 | 中等 |
| E | Execution | 具体计算、执行推导或生成代码 | 较低 |
| T | Transition | 反思、纠错、切换推理方向 | 较高 |

这里的“稀疏度较高”表示：**一行 Attention 权重中，接近零的条目占比更高，注意力更多集中在少量历史位置。** 它不直接等价于“该段思考不重要”。

论文为了测量稀疏度，将低于该行最大 Attention 权重 **1%** 的位置视为稀疏项。举一个纯教学示例，假设：

\[
A=[0.90,\ 0.05,\ 0.04,\ 0.005,\ 0.005].
\]

该行最大值为 \(0.90\)，判别阈值为：

\[
\epsilon=0.01\times0.90=0.009.
\]

最后两个权重低于 \(0.009\)，所以被计入稀疏项。这说明当前 Query 对历史位置的关注并不平均。

**我的理解：** 作者尝试用模型内部的注意力行为代替文本关键词，形成一种可以在线测量的思考状态信号。

### 2.2 “稀疏”不等于“不重要”

论文还进行了反事实的重要性分析：比较保留某个 Thought 片段与抑制该片段时，**最终答案的输出概率分布**发生了多大变化。这里关注的是分布差异，并不等于只看答案文字是否完全相同。

论文在测试设置中观察到一个整体趋势：

\[
\mathrm{Importance}(R)>\mathrm{Importance}(E)>\mathrm{Importance}(T).
\]

也就是说，删除 R 片段对最终答案分布的影响通常更大，E 次之，T 平均较低。但这**不是**说所有 Transition 都没有价值；作者也发现某些关键转折对避免错误循环很重要。

这一点修正了一个容易产生的误解：**Attention 更稀疏，并不能单凭这个事实就判断对应思考没有价值。** 稀疏度主要承担类别识别作用；类别重要性还需要通过其他分析加以支持。

### 2.3 Thought 之间还存在依赖关系

除了单个片段的重要性，论文还研究了不同 Thought 之间的关联：对较早片段的 Attention 进行抑制，观察**后续片段的输出 Logits 分布**变化，以此估计后续思考对早期片段的依赖程度。

作者观察到，当发生 Transition、推理轨迹转向时，某些旧 Thought 对后续步骤的影响通常会减弱。这个发现解释了论文为什么会把 Transition 作为后续主动缩减旧缓存的重要信号。

这里我需要特别区分：**遮蔽历史 Attention 是为了分析片段间的依赖，不是去检测“后续片段的 K 向量有没有变化”这一单一指标。**

## 三、离线 KDE：怎样找出三种思考的边界？

### 3.1 为什么需要 KDE？

即便知道三类 Thought 的稀疏度大致存在低、中、高三个区域，仍然需要回答：

> 具体到一个数值，比如稀疏度 \(0.48\)，究竟应该判为哪一类？

论文发现，在部分 Transformer 层中，随着 Decode 推进，Attention 稀疏度的分布可以出现三个比较明显的峰。作者因此使用 **Kernel Density Estimation（核密度估计，KDE）** 来估计稀疏度的概率密度曲线，再寻找相邻峰之间的谷底作为类别边界。

KDE 的常见形式为：

\[
\hat f(x)=\frac{1}{Mh}\sum_{m=1}^{M}K\!\left(\frac{x-x_m}{h}\right).
\]

| 符号 | 含义 |
| --- | --- |
| \(x_m\) | 第 \(m\) 个 Attention 稀疏度观测值 |
| \(M\) | 样本总量 |
| \(K\) | 核函数，可直观理解为每个样本附近的平滑“小山包” |
| \(h\) | 带宽，决定每个“小山包”的宽窄 |
| \(\hat f(x)\) | 稀疏度的估计概率密度 |

**直觉理解：** 若大量观测聚集在三个区域，把每个观测点附近的平滑曲线叠加起来，就可能看到三个峰。两个峰之间的局部低谷就成为候选分类阈值。

例如，假设观测值主要聚集于 \(0.15\)、\(0.48\)、\(0.85\) 左右，那么两个谷底可能出现在 \(0.30\)、\(0.66\) 附近。**这些数值纯属教学假设，不是论文报告的阈值。**

### 3.2 离线阶段做什么？

论文使用校准 Prompt，先让模型生成输出，收集不同层、不同 Decode 步骤中的 Attention 稀疏度，然后：

1. 对候选层的稀疏度分布使用 KDE。
2. 找出能够较清晰呈现三个峰的层，而不是机械使用所有 Transformer 层。
3. 找到峰与峰之间的局部低谷，得到两个分界阈值 \(\theta_1,\theta_2\)。
4. 汇总校准 Prompt 与入选层的阈值信息，得到在线使用的分类规则。

这里需要强调：离线校准不仅为了求两个阈值，也为了选择**哪些层提供的分类信号更清晰**。在论文的主要实验中，选定层数为 \(|L^*|=4\)，意思是**四个经过筛选的层**，并不是固定使用 Transformer 的第 4 层。

### 3.3 在线阶段做什么？

在线 Decode 时不必对每个新 token 都重新运行 KDE，而是读取离线确定的层集合与阈值，测量选定层的稀疏度并做汇总，然后进行分类。

用教学阈值说明：

\[
\theta_1=0.30,\qquad\theta_2=0.66.
\]

假设四个选定层的稀疏度分别是：

\[
[0.46,\ 0.50,\ 0.49,\ 0.47].
\]

平均稀疏度为：

\[
\bar s=\frac{0.46+0.50+0.49+0.47}{4}=0.48.
\]

按照低稀疏度 E、中稀疏度 R、高稀疏度 T 的划分，\(0.48\) 落在两阈值之间，可判为 Reasoning。

这只是帮助理解分类逻辑的数值示例，真正分类阈值来自模型的离线校准。

论文还使用刷新周期 \(\tau=128\) 来减少在线分类开销：**不是每生成一个 token 就重新判定一次 Thought 类型，而是周期性更新类别。** 这意味着低分类开销与及时发现思考状态转变之间存在权衡。

**这一节我的收获：** KDE 不是在在线推理中训练一个新模型，而是**离线找边界、在线查边界**。它把看似抽象的“思考类型”映射为可度量的 Attention 稀疏度区间。

## 四、TBQ：根据思考类型分配量化精度

识别 Thought 类型之后，论文进入 **TBQ（Think Before You Quantize）**。其目标是：重要性更高的思考片段，不应被分配比低重要性片段还低的 KV 精度。

论文用重要性函数 \(\rho\) 和位宽映射 \(\psi\) 表达这一原则：

\[
\rho(c_1)>\rho(c_2)\ \Longrightarrow\ \psi(c_1)\ge\psi(c_2).
\]

根据论文的整体观察，作者定义：

\[
\rho(R)=2,\qquad \rho(E)=1,\qquad\rho(T)=0.
\]

其中 \(2,1,0\) 是**相对重要性等级**，并非 KV 元素实际使用的 bit 数。

| Thought 类型 | 最初讨论的精度分配 | 论文主要实验采用的配置 |
| --- | --- | --- |
| Reasoning（R） | 8-bit FP8 | 4-bit NVFP4 |
| Execution（E） | 4-bit NVFP4 | 4-bit NVFP4 |
| Transition（T） | 2-bit Ternary | 2-bit Ternary |

因此，论文主要实验采用：

\[
\boxed{\mathrm{R4E4T2}}.
\]

为什么 R 更重要，却仍然可以和 E 都用 4-bit？因为公式里要求的是 \(\ge\) 而不是严格大于 \(>\)：**更重要的类别精度不能更低，但可以相等。** 论文是在对应实验中观察到 R 使用 4-bit 也能保持较好的准确率，才采用更节省空间的配置。

### 4.1 先缓存，再成组量化

作者不是每生成一个 token 就立即对单个 KV 执行完整量化流程，而是使用全精度缓冲区 \(B_{\mathrm{buf}}\)，在收集到规定 Group 数量后再执行量化。论文的主要实验量化分组大小为 \(g=16\)，而 Figure 6 为了说明流程采用 \(g=4\) 的简化展示。

用一句话概括这部分流程：

**生成新 KV → 暂存于全精度缓冲区 → 凑足一个 Group → 按 Thought 类型量化 → 写入压缩后的 KV Cache。**

### 4.2 用一个手算例子理解“量化误差”

我今天用简单的**均匀量化**理解量化与反量化过程。注意：这个公式只是教学工具，不等同于论文中 NVFP4 或三值量化的完整编码规则。

假设：

\[
X=[0.1,\ 0.4,\ -0.2,\ 0.8],\qquad\Delta=0.2.
\]

进行量化：

\[
\hat x=\operatorname{round}\left(\frac{x}{\Delta}\right),
\]

在这个例子中规定半整数向远离零的方向舍入，则：

\[
\hat X=[1,2,-1,4].
\]

反量化为：

\[
X_{\mathrm{rec}}=\Delta\hat X=[0.2,\ 0.4,\ -0.2,\ 0.8].
\]

因此第一个值从 \(0.1\) 近似为 \(0.2\)，引入了 \(0.1\) 的绝对误差。量化减少了表示精度，这种误差可能进一步影响模型计算。

这里的编码结果包含整数 4，**不能把它直接当作 2-bit ternary 编码**。在 ThinKV 的三值量化中，基础离散值集合为：

\[
\{-1,0,+1\}.
\]

如 \([-0.7,0.1,0.8]\) 这样的数据，在合适缩放因子的配合下，可能被近似映射到 \([-1,0,+1]\)。实际还涉及 Scale 的保存和相应的低精度数据格式。

### 4.3 Key 和 Value 为什么用不同的量化维度？

根据论文采用的设计，**Key 以 per-channel 方式量化，Value 以 per-token 方式量化**。

我对 per-channel 的理解是：如果某几个特征通道的数值尺度相差很大，让全部通道共用一个缩放因子，可能使小尺度通道的量化误差偏大；按通道处理可以更好地适配不同尺度。

per-token 则是按每个 token 对应的 Value 表示组织量化参数。两种方式说明：**K 和 V 的数值分布特点不一定相同，不能想当然地用完全一样的量化维度。**

## 五、为什么只做低比特量化可能还不够？

今天学到的一个很有价值的点是：**每个 KV 元素变小，并不代表整个推理任务的缓存占用一定等比例下降。**

推理过程中，模型会继续生成新 token，这些 token 也要新增 KV。如果量化误差改变了推理行为，使模型需要生成更长的思考过程，那么生成长度的增长会抵消部分压缩收益。

可以用近似公式理解：

\[
\mathrm{KVMemory}\propto
\mathrm{RetainedTokenCount}\times
\mathrm{BytesPerKVToken}.
\]

例如，以下数字是**教学假设**：

| 情况 | 生成 Token 数 | 每个 Token 的相对存储单位 | 总单位 |
| --- | ---: | ---: | ---: |
| 原始精度 | 1000 | 16 | 16000 |
| 量化后，长度不变 | 1000 | 4 | 4000 |
| 量化后，生成长度变为 3000 | 3000 | 4 | 12000 |

如果生成长度不变，从 16 单位降到 4 单位，可以节省 75% 的存储；但如果生成长度变为原来的三倍，整体就只节省 25%。该手算忽略了量化 Scale、元数据和其他运行时开销。

所以：**量化优化的是单个 KV 的表示成本；而长输出推理中，KV 的总数量本身也是核心变量。**

论文因此没有停留在 TBQ，而是进一步提出 TBE，让保留的历史 KV 数量也能随推理轨迹变化而调整。今天先读到了这个动机，下一步再专门学习它的触发条件和具体淘汰机制。

## 六、今天最重要的理解变化

### 我原本以为

之前学习 KV Cache 压缩时，我更自然地把问题理解为“找到不重要的 token 或 Head，然后减少它们占用的缓存”。我也容易认为，把 KV 从高精度降到 4-bit、2-bit 后，显存占用就能直接按位宽比例下降。

### 现在我的理解是

ThinKV 提醒我，还可以把**推理过程本身的结构**作为压缩依据。不同 Thought 的 Attention 特征、对答案的影响程度以及与后续步骤的依赖，都可能不同；压缩不应只在单个 token 的分数上做文章。

同时，在长链式推理中，**缓存总成本既与单个 KV 的精度有关，也与最终产生并保留多少 token 有关**。因此，量化和淘汰可能需要共同设计。

### 为什么我的理解发生了变化

主要是今天依次学习了三个证据与机制：

1. **Attention 稀疏度的多峰分布**让我看到，模型内部的数值信号可以用于近似区分思考类型。
2. **反事实重要性与跨 Thought 依赖分析**说明，三种思考类型不仅外观不同，对后续推理的作用也可能不同。
3. **量化与生成长度的关系**让我意识到，单纯降低位宽可能并不能获得同等比例的端到端收益。

## 七、仍然需要继续弄懂的问题

1. **思考类型的可靠性：** 不同模型、任务甚至不同 Transformer 层，都一定有清晰的三个稀疏度峰吗？如果分布不清晰，分类会怎样变化？
2. **在线分类的误差：** 每 \(\tau=128\) 个 token 才刷新一次，是否会错过短暂但关键的推理转折？
3. **量化精度的稳健性：** R4E4T2 在哪些模型或任务上更敏感？是否可能需要针对任务重新设置精度？
4. **TBE 的具体实现：** 旧 Thought 被选中缩减时，到底保留哪些 KV？如何避免丢失重要的纠错线索？

这些是今天阅读后形成的后续研究问题，并不表示我已经对它们进行了实验验证。

## 八、下一步最小行动

下一次继续读 **TBE（Think Before You Evict）**，先完成两件事：

1. 搞清楚什么时候因为 Transition 或缓存预算触发旧 Thought 淘汰。
2. 搞清楚渐进保留策略和 Key 聚类为什么能减少历史 KV，同时尽量避免重要信息一次性丢失。

完成这部分后，再把 TBE 与后面的 **Continuous Thinking（CT）** 联系起来，理解逻辑淘汰如何转变成实际显存槽位复用。
